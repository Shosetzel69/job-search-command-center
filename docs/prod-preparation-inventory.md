## Security role segregation

The PROD stack uses separate credential roles:

| Role | Scope | Long-lived in Worker? |
|---|---|---|
| Cloudflare deploy | Dedicated `Job Search PROD` account only | No |
| GitHub bootstrap/admin | Provision/configure `job-search-runtime-prod`; temporary | No |
| GitHub runtime | `job-search-runtime-prod` only; minimum runtime write + Actions dispatch/read | Yes |
| GitHub source-read | `job-search-command-center` read-only | Runtime repo secret only |
| OAuth | Dedicated PROD client/origin | Client ID public; authorization subject secret/config protected |

GitHub Actions environment-scoped secrets/variables are mandatory before real PROD credentials are added. Repository-level DEV/TEST/PROD secret multiplexing is not accepted for G6.

The text `owner_gate=APPROVED` remains defense-in-depth only; it is not the primary authorization boundary.

Phase 6 builds and validates the new isolated target without switching production traffic.

1. capture immutable legacy PROD backup anchors;

4. validate health/auth/protected APIs and credential isolation on the new target;
5. perform the explicit cutover decision;
6. keep the legacy PROD reachable as rollback until final acceptance.
